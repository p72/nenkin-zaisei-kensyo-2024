# 検証

復元した数理モデル（[`../年金財政検証_数式モデル.md`](../年金財政検証_数式モデル.md) §15）の検証。

## 走らせ方

```bash
python3 -m pytest 検証/                 # 65件（差分テスト8件を含む）
python3 -m pytest 検証/ -m "not slow"   # 差分テストを除く（g++ 不要）
検証/differential/run_all.sh            # 差分テストを8ケースまとめて
python3 検証/verify_kaiteiritu.py       # 公表値との照合サマリ
```

必要なもの: Python 3.6+、pytest（テストスイートのみ）、g++（差分テストのみ）。

## 構え

| 層 | 何を確かめるか | 実体 |
|---|---|---|
| 差分テスト | Python移植が原本Cと一致するか | `differential/` |
| 公表値照合 | 原本の出力が公表値と一致するか | `verify_kaiteiritu.py` |
| 単位テスト | 個々の関数が手計算値と一致するか | `test_econ.py` |

### 差分テスト

原本 `プログラム/国民年金/econ.c` を**無修正でコンパイルして走らせ**、
`differential/port_econ.py` の出力と1要素ずつ突き合わせる。

比較範囲は 2004〜2125年度 × 0〜115歳 × 2系列（単年改定率・老齢基礎年金満額）
= 28,304項目。同梱8ケースで計 226,432項目。

```
$ 検証/differential/run_all.sh
--- econ-3001.csv ---   一致 28304 / 不一致 0
  （……8ケースすべて）
```

`harness.cpp` は `econ()` が参照する外部依存（経済前提ファイル、`seid.c` が
設定する初期値、`cntl.c` の制御変数）だけを与える。`seid()` 本体は呼ばない
（脱退率などの基礎率ファイルが同梱データに無いため）。

**原本への加工**: ビルドは EUC-JP を UTF-8 に変換したコピーに対して行い、
リポジトリ内の原本は読み取りのみ。唯一の加工は、新しい glibc の C23 縮小演算
関数 `fdiv()` と原本の同名関数の衝突を避けるためのビルドディレクトリ内での
識別子改名。`econ.c` は `fdiv` を呼んでいないため検証対象の計算には触れない。

### 移植の範囲

この `differential/` が扱うのは `国民年金/econ.c` の以下の関数まで。

- `econ()` の改定率・満額の算出部分
- `econ_read` / `index_make`
- `kaiteiritu_make_before` / `kaiteiritu_make`
- `round` / `kaiteiritu_marume` / `pension_marume` / `marume_hantei`

**6システム全部の移植は `移植/` にある**（`移植/README.md`）。
①被保険者推計・②厚生年金給付費推計・③国民年金・④基礎年金・
⑤厚生年金収支計算・⑥分布推計、Python 153本・46,314行で、
出力を原本とバイト単位で突き合わせてある。この `differential/` は
そちらより前に書いた、`econ.c` だけの狭い差分テストとして残している。

なお⑥分布推計は初期母集団（`bunpu/kisosuu/`）が同梱資料に無いため
（仕様書 §12.5）、**原本と移植版の一致しか言えない**。公表値との
突き合わせはできない。

`基礎年金/econ.c` の `pre_cut`（2021年度以降のマクロ経済スライド）も移植して
いない。公表値と突き合わせるときだけ、原本から読み取った調整率
（2023年度 0.994、2024年度 0.996）を `extra_macro` として渡している。
差分テストは `extra_macro` を渡さず、原本と同じ条件で回す。
