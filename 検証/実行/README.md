# 実行

2024年財政検証プログラムを最初から最後まで動かす。

```bash
検証/実行/run_pipeline.sh 3001          # 高成長実現ケース
検証/実行/run_pipeline.sh 3002          # 成長型経済移行・継続ケース
検証/実行/run_pipeline.sh 3003 1 1 0 2  # 過去30年投影ケース（労働参加漸進）
検証/実行/run_pipeline.sh 3004 1 1 0 3  # 1人当たりゼロ成長ケース（労働参加現状）
検証/実行/run_all_cases.sh              # 8ケース全部（要約を採って中間を消す）
検証/実行/run_bunpu.sh 2011 3001        # ⑥分布推計
```

`SKIP_BUILD=1` を付けるとビルドを飛ばして前回の実行ファイルを使い回します。
番号を分けたいときは環境変数 `SHISAN`（試算番号）、`ECON`（経済前提番号）、
`WAKU`（外枠番号）、`YOBI`（予備番号）を使います。

引数: 試算番号（= `econ-XXXX.csv` の番号）、出生率、死亡率、入国超過、労働力率。
第2引数以降は省略可（既定は中位推計・労働参加進展）。

必要なもの: `gcc` / `g++`、`iconv`、`patch`、約3GBの空きディスク。
1ケースあたり数分から十数分。

## 原本への手当て

リポジトリ内の原本は**書き換えません**。EUC-JP を UTF-8 に変換したコピーを
ビルドツリーに作り、そこにパッチを当ててビルドします。

### 1. 出力先の絶対パス

プログラムは出力先を `/suuri/rev2024/...` と絶対パスで持っています。そこに
ディレクトリを作って同梱データを置けば動きます。出力先のサブディレクトリは
プログラムが自分では作らないので、スクリプトがあらかじめ用意します。

### 2. `fdiv()` の名前衝突

原本の `snaps.h` / `stdfm.c` が宣言する `fdiv(double, double)` は、新しい
glibc が C23 の縮小演算関数として宣言する `fdiv` と衝突します（戻り値の型が
`double` と `float` で違うため `ambiguating new declaration`）。識別子を
単語単位で一律改名して回避します。計算には触れません。

### 3. `fclose` まわりの潜在バグ3件

`patches/glibc-portability.patch`（実質22行）。Solaris では黙認されていた
ものが glibc では即クラッシュになります。**いずれも計算結果には影響しません。**

| 箇所 | 内容 | glibc での症状 |
|---|---|---|
| `給付費推計/fileio.cpp:331` | `econ.cpp:519` が `fp_map["kaitea"]` を `pseid` のガードより前に `std::map::operator[]` で引くため、厚生年金以外の制度で NULL 要素が挿入される。それを `fcls()` が閉じる | SIGSEGV |
| `基礎年金/main.c:103` | `read_file.c:79` が既に閉じた `fp_in[DOKUZI]` を再度閉じる | `double free or corruption (!prev)` |
| `基礎年金/printout.c:146` | `printout()` は2回呼ばれるが毎回 `fp_out[OUTPUT]` を閉じる | `double free or corruption (out)` |
| `収支計算/fcls.c:64` | `Touitu == 0`（通常試算）で開いていない `ifp_Touitu` を閉じる | SIGSEGV |

1件目は `std::map::operator[]` が「キーが無ければ既定値（NULL）を挿入する」
という C++ の仕様を踏んだものです。書き込み自体は `if(pseid == 0)` で
守られているので、出力は正しいままです。

### 4. カット率ファイルの受け渡し

基礎年金は `bas/rslt/cuta-*.csv` に書き、収支計算は
`emp/rslt/ez_arev/cutr/cuta-*.csv` を読みます。運用スクリプトが間でコピーして
いたと思われますが、同梱の `jikko_bas.sh` にその記述はありません。
`run_pipeline.sh` がコピーします。

## 文字コードについて

ソースを UTF-8 化してビルドするので、実行時の日本語出力も UTF-8 になります。
原本のまま EUC-JP でビルドすれば出力も EUC-JP です。

## ⑥ 分布推計

`run_bunpu.sh` が前段（外枠=2011 / 経済前提=3001 / 予備=125）を流し、
`make_kisosuu.py` で初期母集団を組み立ててから実行します。
1,621,872人・約80秒で完走します。

**基準年齢17歳のコホートだけが数値を出し、27歳以上は `-nan` になります。**

```
01_2011_1_1_17.csv  65,2069,90.2981,9.0983,0.1405,0.4631   合計100%
01_2011_1_1_27.csv  65,2059,-nan,-nan,-nan,-nan
```

加入月数が0なので集計の分母が0になり、ゼロ除算が伝播します。17歳コホートは
生涯を追うコホートなので、分布推計の本来の用途（将来の受給者の年金額分布）に
対応します。**出力を公表値と比較してはいけません。** 仕様書 §12.5。
