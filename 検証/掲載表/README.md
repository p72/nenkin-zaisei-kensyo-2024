# 掲載表との照合

厚生労働省「令和6(2024)年財政検証結果レポート」の**掲載表**と、通し実行の
結果をフル精度で突き合わせます。

- レポート本体: <https://www.mhlw.go.jp/stf/seisakunitsuite/bunya/nenkin/nenkin/zaisei-kensyo/R6suuri_report.html>
- 掲載表（ZIP）: <https://www.mhlw.go.jp/content/12500000/2024report_back.zip>

## なぜ掲載表なのか

概要資料の公表値は四捨五入されています（所得代替率「56.9%」＝有効3桁）。
掲載表は Excel で**フル精度**なので、たとえば2024年度の厚生年金給付費は
`30.012065887192918` 兆円まで書かれています。桁落ちなしで一致・不一致を
判定できるのは、いまのところこの4表だけです。

## 使い方

```bash
# 掲載表を取得して展開
curl -O https://www.mhlw.go.jp/content/12500000/2024report_back.zip
unzip -d 掲載表 2024report_back.zip

# 照合したいケースを通しで実行（1ケース10〜15分）
検証/実行/run_pipeline.sh 3001          # 高成長実現（労働参加進展）
検証/実行/run_pipeline.sh 3002          # 成長型経済移行・継続（進展）
検証/実行/run_pipeline.sh 3003 1 1 0 2  # 過去30年投影（漸進）
検証/実行/run_pipeline.sh 3004 1 1 0 3  # 1人当たりゼロ成長（現状）

pip install openpyxl
python3 検証/掲載表/compare_keisaihyou.py --keisaihyou 掲載表
```

走らせていないケースは「（対象外）」として飛ばすので、1ケースだけでも
動きます。`--table 第3-7-34表` で表を絞れます。

| 掲載表 | 内容 | 内訳 | 計算値の出どころ |
|---|---|---|---|
| 第3-7-29表 | 厚生年金給付費 | 合計・老齢（老齢相当＋通老相当）・障害・遺族 | ⑤ `90nenbe.*_08tou.csv` |
| 第3-7-33表 | 基礎年金給付費 | 合計・老齢・障害・遺族 | ④ `kekka*a.csv` |

## 結果

**5,886項目、不一致ゼロ。** 最大相対差 `1.8e-14`（倍精度の丸め）。

| 掲載表 | 高成長実現 | 成長型経済移行 | 過去30年投影 | 1人当たりゼロ成長 |
|---|---|---|---|---|
| 第3-7-29表 | 388/388 | 388/388 | 388/388 | 144/144 |
| 第3-7-33表 | 388/388 | 388/388 | 388/388 | 144/144 |
| 第3-7-34表 | 485/485 | 485/485 | 485/485 | 180/180 |
| 第3-7-35表 | 485/485 | 485/485 | 485/485 | 180/180 |

ゼロ成長ケースが少ないのは、国民年金の積立金が枯渇して推計が2059年度で
打ち切られるためです（掲載表側も同じ年度まで）。

## 読むときの注意

**`2他計` は小計です。** ⑤の `90nenbe` は
`1比例, 2他計, 3定額, 4経加, 5加給, 6遺加, 7最保` の7区分を出しますが、
`2他計` は `3定額`〜`7最保` の合計です。全区分を足すと二重計上になって
2024年度で34.45兆円（公表30.01兆円）になります。給付費合計は
`1比例 + 2他計`。スクリプトは毎回この関係を検算してから使い、崩れていたら
止まります。

**出力の文字コードはビルド時のソースに従います。** 原本のまま EUC-JP で
ビルドすれば出力も EUC-JP、UTF-8 化してビルドすれば UTF-8 です
（仕様書 §12.2）。同じディレクトリに両方が混在しうるので、スクリプトは
1行目で判別します。

## 照合できていないもの

各表には名目額の隣に「賃金上昇率で2024年度価格に換算した額」の列が
ありますが、これは合っていません。名目額をこちらの比例改定率で割り戻すと
2025年度以降の年次比は完全に一致するのに、全年度に一律 `3.01e-05` の
相対差が残ります。2024年度の1年分だけ公表表が `1.031` ではなく
`1.0310310…` を使っているためで、その率が何かは特定できていません。
導出列なので名目額の照合には影響しません（仕様書 §15.0.2、付録B）。

## 実行領域の場所

通し実行の出力を読む場所は `SUURI_PREFIX` で決まり、既定は
`<リポジトリ>/work/suuri/rev2024` です（`検証/suuri_env.py`、仕様書 §12.1）。
`--shushi-dir`・`--bas-dir` で個別に指定することもできます。

```bash
検証/実行/run_pipeline.sh 3001
python3 検証/掲載表/compare_keisaihyou.py --keisaihyou 掲載表

SUURI_PREFIX=/ python3 検証/掲載表/compare_keisaihyou.py --keisaihyou 掲載表
```
