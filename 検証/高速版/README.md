# 高速版（kosoku）— 数式モデルの実装

> ### ⚠️ 厚生労働省が作成したものではありません
>
> **非公式の実装です。** 厚生労働省の承認・監修・関与を受けていません。公開されている計算
> プログラムから復元した数理モデルを、第三者が Python で書き直したものです。数値が公表値と
> 食い違う場合、**原因はこちら側にあると考えてください。** 公表値が正です。
> 出てくる年金額・所得代替率は、個人の年金見込額ではありません。

`検証/移植/`（原本とビット一致する忠実移植）とは**別の実装**。数理モデル
（[`年金財政検証_数式モデル.md`](../../年金財政検証_数式モデル.md)）を、
単一の軸・データ化した制度・共通の給付型で書き直し、速さと制度変更への
柔軟さを取る。ビット一致と丸めの順序は捨てる。**既定は原本の癖どおり**で公表値を再現する
（下の「既定は原本どおり」）。

設計と決定は [`計画.md`](計画.md)。**正解は常に移植版（＝原本）で、仕様書は
入口。** 高速版は再構築のサブセットなので、仕様書と移植版が食い違えば
移植版が正。

## 動かし方

C/C++ のビルドは要りません。原本の入力データを置いたら、Python（numpy・pyyaml）だけで①〜⑤を通します。

```bash
./fetch.sh program                                    # 厚労省の計算プログラムと入力データ（15MB）
SKIP_BUILD=1 STEPS=0 検証/実行/run_pipeline.sh 3002    # 入力データを work/ に置くだけ（C は建てない）
pip install -r 検証/高速版/requirements.txt
cd 検証/高速版
python3 -m kosoku.cli run 3002                        # 成長型経済移行・継続ケース
python3 -m kosoku.cli run 3002 --option fix_bugs      # 原本の癖（J1・J2・J3・B11）を直した版
```

最後にこう出ます（ケース 3002）。

```
最終所得代替率  計 57.6207  比例 24.9711  基礎 32.6496
調整終了年度    厚年 2024  国年 2037
恒等式          19 本、全部 OK
```

公表値（57.6%、基礎の調整終了 2037年度）と一致し、原本 C の出力とは 15 桁一致します（下の
「既定は原本どおり」）。ケースの番号・レバー（`--option kozax` など）・人口の前提（`--jin` `--qx` `--nc`
`--roudr`）は `python3 -m kosoku.cli run --help`。

テストは `python3 -m pytest -q 検証/高速版/tests`。原本 C の出力（`検証/実行/run_pipeline.sh` で作る）や
公表 Excel（`./fetch.sh` の全部）が無い照合テストはスキップされます。

## フェーズ H の結果（均衡の解法 `BalanceRule`、2026-09-22）

`kosoku/balance.py`。現行の⑤の解法「保険料率を固定し、給付水準（マクロ経済スライドの終了年度）を動かして
2120 年度の積立度合を 1 にする」を **(動かすもの lever) × (合わせる条件 target)** に分けた。yaml
`shushi.balance.rule`（overlay `policy/options/balance_*.yaml`、CLI `--balance`）で切り替える。既定 `current`
は移植版と同じ解法で、答えも同じ（`tests/test_balance.py`）。

| rule | lever | target | 解法 | ケース 3001 の答え |
|---|---|---|---|---|
| `current`（既定） | 給付水準（厚年の終了年度） | 積立金[2119] = 支出[2120] × 1 | 走査 ＋ 割線法（港 `shus_calc8`） | 56.9122、2024／2039（移植版と 13 桁一致） |
| `premium` | 料率（2027 年度から一定。4 制度と第3種に同じ率、**天井なし**） | 同上 | 割線法 → 二分法（`solve_premium`） | 料率 **16.48%**（厚年の調整が 2024 年度で終わって積立金が余るので 18.3% より低い） |
| `payg` | 毎年の料率 | 各年度 収支差 = 積立金 × 物価上昇率（積立金は物価で実質一定） | 逐次（解法なし。`solve_payg`） | 賦課料率 13.8%（2027）→ 13.7%（2040）→ 17.1%（2060）→ 21.4%（2100）→ 22.2%（2125） |
| `perpetual` | 給付水準 | 終期で定常: 収支差[2125] = 積立金[2124] × g（g = 終期の名目賃金上昇率） | 走査 ＋ 割線法（`margin` を差し替え） | 2024 年度で条件を満たす（余剰）ので調整なし |
| `perpetual_premium` | 料率 | 同上 | 割線法 → 二分法 | 料率 **17.62%** |

表の「ケース 3001 の答え」は**高成長実現ケースで、④の基礎年金側は現行の解法のまま**という条件付きの値で、
制度の提案や見通しではない（ケースや基礎年金側の扱いを変えれば動く）。

「給付固定」（lever = 料率）は、厚年の累積調整率を実績年度（2023・2024 年度）までで止めた状態
（`fixed_benefit_Sh`）。**④の基礎年金側は現行の解法のまま**（`St0`）なので、ここで動くのは報酬比例
（厚年 4 制度）だけ。永久均衡は「2125 年度以降は人口・経済前提を据え置いて定常」の近似（時間軸は固定）。
`Options` の 7 本のレバー（§11.1）は BalanceRule と直交する。

**言えること**（構造を変えた設定に正解＝移植版は無い）: (1) 恒等式（収入計 = 部分和、収支差、積立金の
漸化式）が全解法で成り立つ、(2) 既定に戻せば移植版に戻る、(3) 玩具ケース（`tests/toy/test_balance_toy.py`。
1 制度・5 年度の台帳で賦課方式の料率と運用収入を手計算と照合、割線法は一次の問題を 2 回で解く、区間の
自動探索、給付固定の累積調整率）が手計算と合う。各解法が自分の条件を満たすことは⑤の実データで見る
（積立度合 1、毎年 収支差 = 積立金 × 物価、終期の定常条件。相対 1e-8）。

**指標**（`kosoku/indicators.py`。CLI の要約 JSON にも入る）: 実効料率（Σ保険料 ÷ Σ総報酬。賦課方式は
解いた率）、給付総額 ÷ GDP、積立度合、積立金の実質額（2024 年度価格）。**GDP は yaml `gdp.base`（内閣府
SNA 2024 年度確報、10 億円）の 2024 年度を名目賃金上昇率で延ばす近似**（経済前提の CSV に GDP の
成長率が無い。`経済前提一覧.xlsx` の経済成長率に替えるのは後の課題）。世代別の給付負担倍率はフェーズ J
