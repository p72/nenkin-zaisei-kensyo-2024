# レポート数式編との照合

仕様書（`年金財政検証_数式モデル.md`）はソースコードから式を逆算したもの
です。数値が公表値と合っていても（`検証/掲載表/` で5,886項目一致）、
**式の説明が正しいとは限りません**。日本語と数式に書き直す過程で誤りが
入りえます。

答え合わせの原典は厚生労働省自身が書いた数式編です。

| 資料 | 内容 |
|---|---|
| [第7章第1節](https://www.mhlw.go.jp/content/12500000/2024report7.pdf)（p.572〜614） | 財政計算スキーム及び計算式の概要。漸化式が全部書いてある |
| [第3章第5節](https://www.mhlw.go.jp/content/12500000/2024report3.pdf)（p.100〜131） | 被保険者数の将来見通しの作成方法 |
| 第3章第6節（p.132〜150） | 給付水準の将来見通し及び財政見通しの作成方法 |

照合結果は仕様書 **§15.6・§15.7**。誤り5件・欠落8件が見つかり、すべて
直しました。

## このスクリプト

照合のうち、コードを読むだけでは決めきれなかった2点を実行結果で判定します。

```bash
検証/実行/run_pipeline.sh 3001
python3 検証/数式編/verify_shikihen.py
```

`--case 3003` で他のケースも見られます（そのケースを先に走らせておくこと）。

### 検証A — マクロ経済スライドは「掛ける」ではなく「割る」

仕様書の初版は「調整率を掛けて抑制する」と書いていました。実際のコードは
逆で、`max_cut_rate` も `pre_cut` も**1より大きい除数**です。

```
マクロ込みの改定率 = RV ÷ (1 + スライド調整率)
```

`RV` は本来の改定率（⑤の `03summary` の「比例改定率」）、調整率は①が出す
`waku****-m.csv` の値。高成長実現ケースなら**2025〜2038年度の14年ぶんが
差 1e-12 未満で一致**します。

2039年度で一致が切れますが、これが正しい挙動です。**調整終了年度は
スライド調整率を再設定して積立度合をちょうど1に合わせる**ため、通常の式から
外れます（仕様書 §8.3）。一致が切れた年度をそのまま調整終了年度として
報告します。

### 検証B — 均衡条件は2120年度「初」

仕様書の初版は散文で「2120年度**末**に給付費1年分」と書いていて、自分が
載せている式 `F[T−1] ≥ 支出[T]·D` と矛盾していました。正しくは
**2120年度初＝2119年度末**です。

| 量 | 値 |
|---|---|
| 2119年度末 積立金 ÷ 2120年度 支出 | **1.000000000000** |
| 2120年度末 積立金 ÷ 2120年度 支出 | 0.915078 |

2119年度末の積立金と2120年度の支出は**同一の値まで収束**しています
（§8.2 の二分法が合わせているのは `T−1` の側）。

## 確認できなかったもの

レポート第3章第6節 p.265 の**給付水準調整割合 `R(N,X)` の漸化式**
（`N ≥ KE+1` で `R(N,X) = R(N−1,X−1)`）は検証できていません。

`R(N,X)` は年金1本あたりの調整割合ですが、⑤の出力（`90nenbe`）は年齢別に
集計した給付費です。同じ年齢の中に裁定年度の違う受給者が混ざり、累積した
調整量が裁定年度ごとに違うため、集計値の比は `R(N,X)` になりません。年齢を
1つずらして追うと**最大 1.9e-03 ずれます**。分解して取り出す術が出力側に
ないので、未確認のまま付録Bに残しています。
