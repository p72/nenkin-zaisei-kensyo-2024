# レポート数式編との照合

仕様書（`年金財政検証_数式モデル.md`）はソースコードから式を逆算したもの
です。数値が公表値と合っていても（`検証/掲載表/` で5,886項目一致）、
**式の説明が正しいとは限りません**。日本語と数式に書き直す過程で誤りが
入りえます。

答え合わせの原典は厚生労働省自身が書いた数式編です。

| 資料 | 内容 |
|---|---|
| [第7章第1節](https://www.mhlw.go.jp/content/12500000/2024report7.pdf)（p.572〜614） | 財政計算スキーム及び計算式の概要。漸化式が全部書いてある |
| [第3章第5節](https://www.mhlw.go.jp/content/12500000/2024report3.pdf)（p.100〜131） | 被保険者数の将来見通しの作成方法 |
| 第3章第6節（p.132〜150） | 給付水準の将来見通し及び財政見通しの作成方法 |

照合結果は仕様書 **§15.6・§15.7**。誤り5件・欠落8件が見つかり、すべて
直しました。

## スクリプト

| スクリプト | 内容 | 通し実行 |
|---|---|---|
| `verify_shikihen.py` | マクロ経済スライドの向き（除数）と均衡条件の添字を実測で判定 | 必要 |
| `verify_cc.py` | ⑤の `Cc[]` 項目名（§7.2）と `R(N,X)` の漸化式（§8.4） | 検証Bのみ必要 |
| `verify_bunpu_func.py` | ⑥分布推計の関数とレポート第5章の手順の対応（§10.4・§10.7） | 不要 |

```bash
検証/実行/run_pipeline.sh 3001
python3 検証/数式編/verify_shikihen.py
python3 検証/数式編/verify_cc.py
python3 検証/数式編/verify_bunpu_func.py
```

`verify_shikihen.py` と `verify_cc.py` は `--case 3003` で他のケースも
見られます（そのケースを先に走らせておくこと）。`verify_cc.py` と
`verify_bunpu_func.py` はリポジトリのルート以外から呼ぶときは `--root` を
渡してください。

### verify_shikihen.py

#### 検証A — マクロ経済スライドは「掛ける」ではなく「割る」

仕様書の初版は「調整率を掛けて抑制する」と書いていました。実際のコードは
逆で、`max_cut_rate` も `pre_cut` も**1より大きい除数**です。

```
マクロ込みの改定率 = RV ÷ (1 + スライド調整率)
```

`RV` は本来の改定率（⑤の `03summary` の「比例改定率」）、調整率は①が出す
`waku****-m.csv` の値。高成長実現ケースなら**2025〜2038年度の14年ぶんが
差 1e-12 未満で一致**します。

2039年度で一致が切れますが、これが正しい挙動です。**調整終了年度は
スライド調整率を再設定して積立度合をちょうど1に合わせる**ため、通常の式から
外れます（仕様書 §8.3）。一致が切れた年度をそのまま調整終了年度として
報告します。

#### 検証B — 均衡条件は2120年度「初」

仕様書の初版は散文で「2120年度**末**に給付費1年分」と書いていて、自分が
載せている式 `F[T−1] ≥ 支出[T]·D` と矛盾していました。正しくは
**2120年度初＝2119年度末**です。

| 量 | 値 |
|---|---|
| 2119年度末 積立金 ÷ 2120年度 支出 | **1.000000000000** |
| 2120年度末 積立金 ÷ 2120年度 支出 | 0.915078 |

2119年度末の積立金と2120年度の支出は**同一の値まで収束**しています
（§8.2 の二分法が合わせているのは `T−1` の側）。

### verify_cc.py

⑤収支計算の `Cc[]` 項目名と、給付水準調整割合 `R(N,X)` の実装を確かめます。
どちらも初版では付録Bに「確定できていない」として残していた項目で、
**どちらも探す場所が違っていた**だけでした。

- **検証A** 項目名は `shus_out.c:449-452` の出力ヘッダにある。ただし直後の
  ループが `i==2 || i==7 || i==8 || (13<=i<=15) || i==22 ||
  (i>=25 && i!=27 && i!=30)` を読み飛ばすので、ヘッダの列とループの `i` を
  突き合わせないと対応が取れない。印字20個・ヘッダ20列で一致する。
- **検証B** 実データで検算。収入計・支出計・国庫負担が内訳の和になり、
  `独自給付 = 30.012066兆円` が掲載表の厚生年金給付費と一致する。
- **検証C** `R(N,X)` の3分岐がソースに代入文としてある。
  `Escutrrh[k][x] = Escutrrh[k-1][x-1]` がレポートの
  `R(N,X) = R(N−1,X−1)` そのもの。均衡条件の添字が `kend−1` であることも
  ここで確認できる。

### verify_bunpu_func.py

⑥分布推計の関数が、レポート第5章第1節 p.434-439 の手順①〜⑥と補論（2）に
対応することを確かめます。ソースを読むだけなので通し実行は不要です。

- **検証A** `kisoritsu01`〜`08` の8ディレクトリがレポートの基礎率
  （`MatSedSni`・`PrbSedSni`・`PrbHshSni`・`PrbHshSet` など）に対応する
- **検証B** 乱数の付与 → 乱数と前年度加入制度での二段安定ソート →
  優先順の割当（`func06a/06b` → `func07a/07b` → `func08a` → `func09b`）が
  補論（2）のステップ1〜3と一致する
- **検証C** **繰上げ・繰下げを扱っていない**（該当する定数が0件、
  `main_var001 = 65` でループが止まる）。初版はここを取り違えていた

## 確認できなかったもの

掲載表の「2024年度価格」列の**2024年度の換算率**だけが未特定です。系列自体は
こちらの比例改定率そのものだと確定しました（2026年度以降は最大相対差
`6.0e-15`）が、2024年度の1要素が `1.031` ではなく厳密に
`1030/999 = 1.030/0.999` で、その出所が公表資料から辿れません。

```bash
python3 検証/掲載表/compare_keisaihyou.py --keisaihyou 掲載表 --deflated
```

導出列なので名目額の照合（5,886項目全一致）には影響しません。
