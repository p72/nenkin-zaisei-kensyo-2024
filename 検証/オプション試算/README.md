# オプション試算と財政見通しの照合

厚生労働省「令和6(2024)年財政検証結果」の**詳細結果等**に入っている財政見通しの
Excel と、通し実行の結果をフル精度で突き合わせます。

| 資料 | 中身 |
|---|---|
| [財政検証結果レポート](https://www.mhlw.go.jp/stf/seisakunitsuite/bunya/nenkin/nenkin/zaisei-kensyo/R6suuri_report.html) | 本体（全7章） |
| [詳細結果等1](https://www.mhlw.go.jp/content/001286770.zip)（28MB） | 通常試算 財政見通し34本・被保険者数23本 |
| [詳細結果等2](https://www.mhlw.go.jp/content/001286771.zip)（37MB） | オプション試算 財政見通し92本・被保険者数27本 |

`検証/掲載表/` は給付費・拠出金・交付金の4表だけですが、こちらは**収入・支出の
全項目と所得代替率・モデル年金額**が四捨五入なしで載っています。

## 使い方

```bash
pip install openpyxl
curl -O https://www.mhlw.go.jp/content/001286770.zip
curl -O https://www.mhlw.go.jp/content/001286771.zip
```

ZIP のファイル名は Shift_JIS なので `unzip` では「File name too long」で
こけます。`python3 -c` で展開してください。

```python
import zipfile, os
z = zipfile.ZipFile('001286771.zip')
for n in z.namelist():
    d = n.encode('cp437').decode('cp932')
    p = os.path.join('opt2', d)
    os.makedirs(os.path.dirname(p), exist_ok=True)
    if not d.endswith('/'):
        open(p, 'wb').write(z.read(n))
```

照合したいケースを通しで実行してから、対応する xlsx を渡します。

```bash
検証/実行/run_pipeline.sh 3001
python3 検証/オプション試算/compare_option.py \
    --published '詳細結果等/…/01.　人口中位　高成長実現ケース.xlsx'
```

## 4つのレバー

`run_pipeline.sh` の環境変数です。入力位置は原本で1つずつ確認しました。

| 環境変数 | オプション | ②給付費推計 | ④基礎年金 | ⑤収支計算 |
|---|---|---|---|---|
| `KOZAX` | 65歳以上の在職老齢年金の撤廃 | `flg_kozax`（入力8） | ― | ― |
| `HOUJOU` | 標準報酬月額の上限の見直し | `houjou`（入力9） | ― | `Flg_Houjou`（入力5） |
| `TOUGOU` | マクロ経済スライドの調整期間の一致 | ― | `argv[15]` | `Touitu`（入力6） |
| `DMACRO` | 名目下限措置の撤廃 | ― | `argv[11]` | `Flg_Dmakuro`（入力8） |
| `CARRY` | キャリーオーバー（1=あり、既定） | ― | `argv[10]` | `Flg_Kmakuro`（入力7） |

既存の `KAKUDAI`（適用拡大）・`SIGO`（基礎45年化）と合わせて6本です。

**`CARRY` の極性は④と⑤で逆です。** ④の `argv[10]` は「1=キャリーオーバー
あり」、⑤の `Flg_Kmakuro` は「1=キャリーオーバー撤廃」（収支計算/cntl.c:168）。
スクリプトが `1 - CARRY` を⑤へ渡します。

### 基礎年金側を据え置くオプション（`STEPS=25`）

高在老撤廃と標準報酬上限は報酬比例にしか効かないので、基礎年金の財政は
動きません。公表値もそうなっていて、**No.25（高在老撤廃）の国民年金シートは
No.03（通常試算）と1ビット違いません**。厚生年金シートでも基礎年金拠出金・
保険料収入・標準報酬総額の相対差が0で、給付費から先だけ動きます。

ところが②は `flg_kozax` を立てると `kiso.*` の中身がわずかに変わります
（老在を老退として扱う副作用）。そのまま③④を流すと基礎年金のカット率が
`1e-7` ほどずれて公表値と合いません。**③④を通常試算のまま据え置いて②と⑤
だけ流し直す**のが正解です。

```bash
検証/実行/run_pipeline.sh 3003 1 1 0 2                      # 通常試算
KOZAX=1 STEPS=25 SKIP_BUILD=1 \
    検証/実行/run_pipeline.sh 3003 1 1 0 2                  # 公表 No.25
```

調整期間の一致・名目下限撤廃・キャリーオーバーは基礎年金側も動くので
（公表値もそうなっている）①〜⑤を通しで流します。

### 調整期間の一致は④を2回まわす

```
④ 1周目  CUT_KOTEI=0   基礎年金が自前で有限均衡を解き、比例側へ渡す
                        provide と ss=7,8 付きの KYOSHUTUKIN を書く
⑤        Touitu=1      基礎と比例を一括で均衡させ、統一カット率を
                        cuta/cutb-…-1120-{YOBI2} に書く
④ 2周目  CUT_KOTEI=1   その統一カット率を読んで基礎年金の見通しを作り直す
```

`YOBI2` は `YOBI` と別の3桁にしてください。同じだと⑤が同名のファイルを2つの
ハンドルで書き込み用に開いて壊れます（スクリプトが弾きます）。

```bash
TOUGOU=1 YOBI2=001 検証/実行/run_pipeline.sh 3001
python3 検証/オプション試算/compare_option.py \
    --published '…/21.　調整期間の一致　人口中位　高成長実現ケース.xlsx' \
    --bas-yobi 001
```

**公表の調整期間一致には国民年金シートがありません**（一元化シートと基礎年金
シートだけ）。④の2周目は基礎年金の見通しを作り直すためのもので、国民年金の
収支見通し欄（運用収入・年度末積立金）は1周目のものが正です。2周目は
`tyousei()` を呼ばないので積立金の漸化式が回らず、その2欄だけ1周目と
`1e-4` ほど違う値になります。照合には1周目の値（⑤経由）を使っています。

## 公表側の2つのレイアウト

シート名で見分けます。

| レイアウト | シート | 出てくる資料 |
|---|---|---|
| 一元化 | 国年年金及び厚年年金／基礎年金 | 調整期間の一致を含むオプション |
| 制度別 | 厚生年金／国民年金／基礎年金 | 通常試算とその他のオプション |

調整期間の一致では⑤が国民年金の収支まで取り込むので、`01shushi.*_08tou.csv`
が公表の「国民年金及び厚生年金」そのものになります。このとき国民年金の独自
給付は⑤の2つの欄に散ります。

```
独自給付 = 厚年の独自給付 ＋ 国年の寡婦年金                （shus.c:113）
事務費   = 厚年の事務費   ＋ 国年の一時金・付加年金・業務勘定への繰入
                                                          （shus.c:382）
```

公表は「報酬比例」に国年の独自給付を全部入れ、「その他支出」を事務費と業務
勘定への繰入だけにしているので、`provide` から一時金・付加年金を取って
付け替えます。

## こちら側の出どころ

| 公表の欄 | こちら |
|---|---|
| 厚生年金・一元化の収支 | ⑤ `01shushi.*_08tou.csv`「収支見通し【スライド調整後】」（億円） |
| 国民年金の収支 | ④ `kekka*a.csv`「収支見通し」（円） |
| 所得代替率・モデル年金額 | ⑤ `03summary.*_08sum.csv`「経済前提等」 |
| 国年の一時金・付加年金 | ④ `provide*.csv`「独自給付費等（年度間値）」（円） |
| 2024年度価格への換算率 | ④ `kekka*a.csv` の「保険料改定率」列 |

`_08tou` は4制度（厚年・国共済・地共済・私学）の合計です。`_08kou` は第1号
厚生年金被保険者だけなので公表の「厚生年金」には対応しません（2024年度で
59.9兆円 対 68.7兆円）。ここを間違えると全項目が13%ずれます。

項目の読み替えで注意がいるのは3つです。

- **国庫負担** ＝ 国庫負担 ＋ 支援額収入。調整期間一致のとき国年の一時金付加分
  国庫・付加年金国庫が「支援額収入」に入る（shus.c:381）。通常試算では0。
- **その他収入** ＝ 納付金 ＋ 妻積み分配等（＋国年のこども子育て繰入）。
  「こども・子育て支援特別会計からの繰入」は④では保険料の隣に出ますが、公表は
  その他収入に入れています（2026年度から出てくる）。
- **モデル年金額・手取り収入** は「実質<対物価>」なので `03summary` の
  **物価割り戻し**の列を使う。名目の列と混ぜると2025年度から合わなくなる。

## 2024年度価格の換算率（付録Bの最後の1件が解けた）

公表表の「2024年度価格」欄は、名目額に `kakaku[2024] / kakaku[k]` を掛けた
ものです。`kakaku[]` は④が持つ2004年度価格への換算率（基礎年金/econ.c:312-375。
2004年度を1として名目賃金上昇率を積み上げ、2025年度＝`MARUME_NENDO` で
小数3桁に丸める）。

```
kakaku[2023] = 0.972
kakaku[2024] = 0.999
kakaku[2025] = 1.030
```

`検証/掲載表/` で「2024年度価格の列だけ全年度に一律 3.01e-05 の相対差が残り、
2024年度の1年分だけ 1.031 ではなく 1030/999 = 1.031031031… が使われている」と
書いていたものは、この

```
kakaku[2025] / kakaku[2024] = 1.030 / 0.999 = 1.031031031031031
```

そのものでした。丸めた2つの数の比なので、賃金上昇率 1.031 とはわずかに違います。
名目額に `kakaku[2024]/kakaku[k]` を掛ける形で、公表の「年度末積立金
（2024年度価格）」194項目が**最大相対差 6.3e-15** で再現できます。
仕様書 §15.0.2・付録B を更新しました。

## 照合していないもの

基礎年金シート（基礎年金給付費・国庫負担・拠出金単価・拠出金算定対象者数）は
まだ照合していません。拠出金算定対象者数については、高在老撤廃ケースで公表値と
**相対差0**（全年度）であることを確認済みです。給付費・拠出金は
`検証/掲載表/` の第3-7-33表・第3-7-34表で通常試算4ケース分を照合しています。
