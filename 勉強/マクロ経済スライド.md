# マクロ経済スライドについて厚労省のC/C++コードで解説する

2024年財政検証で厚生労働省が公表した計算プログラムを読みながら、
**マクロ経済スライド**（年金額の伸びを賃金・物価の伸びより少し抑えて、給付水準を
ゆっくり下げる仕組み）がコードの上でどう計算され、**いつ終わるか**がどう決まるのかを追う。

- コードは原本 `papers/001365945/プログラム/` のもの。行番号は EUC-JP を UTF-8 に
  変換したコピーで確かめた（原本とは行がずれない）
- 数字は、このリポジトリで計算プログラムを動かした出力から取った（現行制度）。
  公表の財政見通しと照合済み
- 先に [基礎年金拠出金.md](基礎年金拠出金.md) を読むと、ステップ5の「国年の財布」が分かりやすい
- 数式としての整理は [年金財政検証_数式モデル.md](../年金財政検証_数式モデル.md) の
  §5.7「改定率とマクロ経済スライド」と §8「有限均衡」

---

## 0. 全体像：3つの系統で分担している

```
① 被保険者推計   スライド調整率をつくる（被保険者数の減り方 ＋ 0.3%）
                    ↓ 外枠ファイル waku{番号}-m.csv
④ 基礎年金       改定率に調整をかける → 累積カット率 → 国年の財布が
                  2120年度に均衡する「終了年度」を探す（基礎年金の水準）
                    ↓ カット率ファイル cuta/cutb
⑤ 厚年収支       同じ調整を報酬比例にかけ、厚年の財布が均衡する終了年度を探す
                  （報酬比例の水準）→ 所得代替率
```

**基礎年金と報酬比例で、調整の終わる年度が別々に決まる**（2段階の有限均衡）。
過去30年投影ケースでは、基礎年金は2057年度まで、報酬比例は2026年度まで調整が続く。

## ステップ1：スライド調整率をつくる（①`cutout.c`）

[`被保険者推計/cutout.c`](../papers/001365945/プログラム/被保険者推計/cutout.c)（42〜118行目）。

```c
JYUMYO = 0.997 ;                                   // 平均余命の伸びを勘案した一定率 0.3%

// 公的年金の被保険者数（年度平均）の、3年分の変化の3乗根 × 0.997
cutritu[年度] = pow( ( kouteki_cent[年度-2] - TMQ[年度] )
                   / ( kouteki_cent[年度-5] - TMP[年度] ) , 1.0 / 3.0 ) * JYUMYO ;

if ( cutritu[年度] > 1.0 ) cutritu[年度] = 1.0 ;    // 被保険者が増えても調整率はマイナスにしない
cutritu2[年度] = 1.0 / cutritu[年度] - 1.0 ;         // 「割る数 − 1」の形で書き出す（小数4桁）
```

- `kouteki` は公的年金の被保険者の合計：厚生年金（70歳未満）＋適用拡大の分＋共済＋3号＋1号
  （44〜67行目）。前年度末と当年度末の平均が `kouteki_cent`（69〜81行目）
- 「2年前 ÷ 5年前」の3乗根なので、**2〜4年度前の3年平均の減少率**になる
- `TMP`・`TMQ` は基礎年金45年化のときだけ使う補正（60〜64歳を除く）

出力 `waku3003-m.csv`（過去30年投影）の値は、たとえば次のとおり。

| 年度 | 2025 | 2026 | 2030 | 2035 | 2040 | 2050 | 2060 | 2080 | 2100 |
|---|---|---|---|---|---|---|---|---|---|
| 調整率 | 0.37% | 0.34% | 0.81% | 1.18% | 1.42% | 1.47% | 1.21% | 1.60% | 1.43% |

少子化で被保険者が減るほど、調整率は大きくなる。

> 適用拡大や3号廃止は、人を号の間で**移すだけ**なので、`kouteki`（合計）はほとんど動かない。
> 調整率ではなく、**どちらの財布が負担するか**（[基礎年金拠出金.md](基礎年金拠出金.md)）を通じて効く。

## ステップ3：改定率に調整をかける（④`econ.c`）

[`基礎年金/econ.c`](../papers/001365945/プログラム/基礎年金/econ.c)。
調整率は `cut_read()`（282〜305行目）で読み、**`1 + 調整率`** にして `max_cut_rate` に持つ。

```c
max_cut_rate[年度] = 1. + buffer[1];   // 例：2025年度は 1.0037
```

コードは調整を**掛ける**のではなく**割る**形で持つ。これが読むときの落とし穴である。

### 通常（キャリーオーバーあり、99〜158行目）

```c
pre_cut[年度][年齢] = max( 1.0 , min( max_cut_rate[年度] / T[前年度][前の年齢] ,
                                     kaiteiritu[年度][年齢] ) );
T[年度][年齢]       = T[前年度][前の年齢] / max_cut_rate[年度] * pre_cut[年度][年齢];
```

マクロ込みの改定率は `kaiteiritu ÷ pre_cut` になる。`pre_cut` に3つの制度のルールが入っている。

| 式の部分 | 制度のルール |
|---|---|
| `min( …, kaiteiritu )` | 割る数は本来の改定率を超えない ＝ **年金額を名目で下げるところまでは調整しない** |
| `max( 1.0, … )` | 割る数は1を下回らない ＝ 本来の改定率がマイナスの年は調整しない（**名目下限**） |
| `/ T[前年度]` | 名目下限で調整しきれなかった分を翌年度以降に回す（**キャリーオーバー**、2016年改正） |

`T` は未調整分の残高である。調整が満額効いた年は
`T = (T前 / max_cut_rate) × (max_cut_rate / T前) = 1` となり、自動的に1に戻る。

### 実績年度はハードコード（112〜135行目）

```c
if( nendo == 2022 ) { pre_cut = 1.;            T = ( 1 / 0.997 ); }   // 未調整分0.3%を翌年へ
if( nendo == 2023 ) { pre_cut = ( 1 / 0.994 ); T = 1.; }              // 実施済み −0.6%
if( nendo == 2024 ) { pre_cut = ( 1 / 0.996 ); T = 1.; }              // 実施済み −0.4%
```

### オプションの分岐

- **キャリーオーバーなし**（56〜98行目、`Kurikoshim == 0`）：`T` を使わず
  `max( 1.0, min( max_cut_rate, kaiteiritu ) )`
- **名目下限の撤廃**（160〜190行目、`D_MACRO == 1`）：`min` を外して `max( 1.0, max_cut_rate )`。
  本来の改定率がいくら低くても満額調整する

どちらも `検証/実行/run_pipeline.sh` の `CARRY`・`DMACRO` で切り替えられる
（④の引数 `argv[10]`・`argv[11]`、`cntl.c:53-54`）。

## ステップ4：累積カット率をつくる（④`econ.c:192-215`）

```c
for( counter = 調整開始 ; counter <= 最終年度 ; counter++ )       // 調整をかける年度
  for( nendo = counter ; … )                                      // 影響を受ける年度
    for( nenrei = … )
      for( c_nendo = counter ; … )                                 // 「調整終了年度」の候補
        cut_ruiseki[c_nendo][nendo][nenrei] /= pre_cut[counter][年齢];
```

`cut_ruiseki[c][年度][年齢]` は、**調整を c 年度で終えた場合**の、その年度・年齢の
年金額の縮み具合（1より小さい）である。終了年度の候補ごとに全部作っておくのがポイントで、
次のステップはこの表から候補を選ぶだけで済む。

2023・2024年度の実施済みの調整がすでに入っているので、**2024年度で終えた場合は
0.994 × 0.996 ＝ 0.990024**。これが「調整なし」の値で、これ以上は上がらない（天井）。

## ステップ5：終了年度を探す（④`tyousei.c`）

[`基礎年金/tyousei.c`](../papers/001365945/プログラム/基礎年金/tyousei.c)。
**国民年金の財布が2120年度に積立度合1で均衡する**終了年度を探す。

### 5-1 年度を1年刻みで探す（66〜129行目）

```c
for( c_nendo = C_NENDO + 1 ; c_nendo <= T_NENDO ; c_nendo++ )    // 終了年度の候補
{
    … c_nendo で終える改定率に作り直す …
    Atamawari_cut( c_nendo );          // 給付費と拠出金を計算し直す
    … 国年の積立金を2120年度まで回す …

    if( Tumitate[2119年度末] < Shishutu[2120年度] * T_DOAI )    // まだ足りない
        …（2120年度まで行っても足りなければ「調整できません」）
    else if( c_nendo >= 2024 )
        break;                                                  // 足りた → この年度
}
S_C_NENDO = c_nendo;
```

- `T_NENDO = 2120`、`T_DOAI = 1`。条件は「**2119年度末の積立金 ≥ 2120年度の支出1年分**」
- 調整を長く続けるほど給付が減って積立金が残るので、**初めて足りた年度**が答え
- `Atamawari_cut` の中で `Cut_ritu` が給付費に掛かり（[基礎年金拠出金.md](基礎年金拠出金.md) のステップ2）、
  拠出金 → 国年の財布へとつながる

### 5-2 最後の1年を二分法で合わせる（133〜230行目）

1年刻みだと粗いので、終了年度の1年分だけ、累積カット率を「前年度で終えた値」と
「その年度で終えた値」の間で**二分法を128回**繰り返して合わせる（149行目 `while( counter <= 128 )`）。
倍精度の丸め誤差まで収束する。

同じ100年分の財政計算を何百回も回すので、ここがプログラムでいちばん重い部分である。

## ステップ6：基礎年金の所得代替率（④`tyousei.c:231-242`、`dtst.c:108-109`）

```c
MODEL_PENSION = 133960 / ( 0.994 * 0.996 ) ;   // 夫婦2人の基礎年金（月額）。実施済みの調整を戻した値
MODEL_WAGE    = 369915;                         // 現役男子の平均手取り（月額）

代替率換算 = MODEL_PENSION × cut_ruiseki[終了年度][終了年度][63歳] ÷ MODEL_WAGE × 100
```

実際の値（④のログ）。

| ケース | 終了年度 | 最終カット率 | 基礎年金の所得代替率 |
|---|---|---|---|
| 過去30年投影 | **2057** | 0.6975 | **25.5%** |
| 高成長実現 | **2039** | 0.8732 | **31.9%** |
| （調整なし＝天井） | 2024 | 0.990024 | 36.2% |

検算：135,309.85 × 0.6975487 ÷ 369,915 × 100 ＝ 25.515%（ログの値と一致）。

過去30年投影では、基礎年金を今より約3割（1 − 0.6975/0.990 ≒ 30%）縮めて、やっと国民年金の財布が
2120年度まで持つ、ということになる。

## ステップ7：報酬比例は⑤で同じことをする（`shus_calc.c`）

[`厚生年金/収支計算/shus_calc.c`](../papers/001365945/プログラム/厚生年金/収支計算/shus_calc.c)。
④が決めた基礎年金の水準（＝基礎年金拠出金）を前提に、**厚生年金の財布**で終了年度を探す。

```c
kend = atoi(Cutrfile3) + 100;                              // 2120年度（201行目）

if(k==23) rh[k][x] = 1.0/0.994;                            // 実績年度（236〜237行目）
if(k==24) rh[k][x] = 1.0/0.996;

for(k = Kijun+1; k < Ke && flg_end > 0; k++){               // 268〜290行目
    Escutrrh[k][x] = Escutrrh[k-1][x-1] / rh[k][x];         // k 年度まで調整を延ばす
    for(kk = k+1; kk <= Ke; kk++)
        Escutrrh[kk][x] = Escutrrh[kk-1][x-1];              // それ以降は据え置き
    … 収支を計算し直す …
    f1 = Cc[ii][20][kend-1] - Cc[ii][11][kend] * Ca;        // 2119年度末の積立金 − 2120年度の支出
    if(f1 >= 0.0 && k >= k_jisseki){ kn = k; flg_end = 0; } // 初めて均衡 → 終了年度
}
```

`rh` も④の `pre_cut` と同じく**割る数**（`1 + 調整率`）である。その後、④と同じく
最後の1年を二分法で合わせる（`rrh_max`・`rrh_min`、294〜295行目〜）。

| ケース | 報酬比例の終了年度 | 報酬比例の所得代替率 |
|---|---|---|
| 過去30年投影 | 2026 | 24.9% |
| 高成長実現 | 調整なし（2024） | 25.0% |

**基礎年金の水準は国民年金の財布だけで決まり、報酬比例の水準は基礎年金の水準と
厚生年金の財布の両方で決まる。** 順番が非対称なのは、国民年金の支出の大部分が
基礎年金拠出金で、国民年金は基礎年金の調整でしか均衡できないからである（数式モデル §8.2）。

## まとめの図

```

                                        │
④ 本来の改定率 ÷ pre_cut（名目下限・キャリーオーバー込み）
        │
        ├─ 累積カット率 cut_ruiseki[終了年度の候補][年度][年齢]
        │
        └─ 終了年度を探す：国年の財布が 2120年度に積立度合1 ？
              1年刻み → 最後の1年を二分法128回 ── 基礎年金の水準（25.5%）
                                        │ 基礎年金拠出金
⑤ 同じ調整を報酬比例に ── 厚年の財布が 2120年度に積立度合1 ？ ── 報酬比例の水準（24.9%）
                                        │
                              所得代替率 50.4%（過去30年投影）
```
