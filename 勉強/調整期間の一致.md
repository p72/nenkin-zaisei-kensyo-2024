# マクロ経済スライドの調整期間の一致について厚労省のC/C++コードで解説する

2024年財政検証で厚生労働省が公表した計算プログラムを読みながら、
**調整期間の一致**（基礎年金と報酬比例で、マクロ経済スライドの調整を同じ年度に終える）が
コードの上でどう実現されているかを追う。

- コードは原本 `papers/001365945/プログラム/` のもの。行番号は EUC-JP を UTF-8 に
  変換したコピーで確かめた（原本とは行がずれない）
- 数字は、このリポジトリで計算プログラムを動かした出力から取った
- 先に [有限均衡.md](有限均衡.md)（2段階で解く仕組み）を読むと分かりやすい
- 数式モデルでは §8.2（2段階）と §11（オプションのスイッチ）

---

## 0. 何が問題で、何をするのか

通常の財政検証は、**2つの財布を別々に**均衡させる（[有限均衡.md](有限均衡.md) のステップ5）。

- 国民年金の財布 → 基礎年金の調整終了年度
- 厚生年金の財布 → 報酬比例の調整終了年度

その結果、過去30年投影では基礎年金が2057年度まで、報酬比例が2026年度まで調整される。
**基礎年金だけが30年以上長く削られ続ける**ことになる。

調整期間の一致は、**国民年金と厚生年金を1つの財布とみなして一緒に均衡させ**、基礎年金と
報酬比例に**同じ調整（同じ終了年度）**をかける方法である。2024年財政検証ではオプション試算の
1つとして計算された。2025年の年金制度改正法の修正で、政府は基礎年金と厚生年金の調整を
同時に終えるために必要な法制上の措置を講ずるものとされた
（[年金制度の仕組みと考え方 第7](https://www.mhlw.go.jp/stf/nenkin_shikumi_007.html)）。

## ステップ1：入り口（`TOUGOU=1`）

`検証/実行/run_pipeline.sh` の環境変数 `TOUGOU` がスイッチである。④⑤の両方に渡り、
**④を2回まわす**。

```
④ 1周目（CUT_KOTEI=0）  いつもどおり基礎年金の終了年度を解く。
                         あわせて、⑤に渡す国民年金の収支を書き出す
        ↓
⑤（Touitu=1）          国民年金の財布を厚生年金の財布に足し、基礎と比例に同じカットをかけて
                         一体で均衡させる。統一カット率を書き出す（予備番号 YOBI2）
        ↓
④ 2周目（CUT_KOTEI=1）  統一カット率を読んで、国民年金の見通しを作り直す
```

④の引数では `argv[15]` が `TOUGOU`、`argv[16]` が `CUT_KOTEI`
（[`基礎年金/cntl.c`](../papers/001365945/プログラム/基礎年金/cntl.c):58-59）。

## ステップ2：④が国民年金の収支を渡す

④の計算そのものは変わらない。`TOUGOU == 1` のとき、**出力が2つ増える**。

1. **`provide{番号}.csv`**：国民年金の収支項目（保険料・国庫負担・積立金など）。
   出力ファイル表の `D` 印の行を、`TOUGOU` のときだけ書く設定にする
   （[`基礎年金/file_open.c`](../papers/001365945/プログラム/基礎年金/file_open.c):84-93）
2. **`KYOSHUTUKIN` の追加ブロック（`ss = 7, 8`）**：国民年金の分の基礎年金給付を年齢別に書く
   （[`基礎年金/file_write_kakyu.c`](../papers/001365945/プログラム/基礎年金/file_write_kakyu.c):386〜）

## ステップ3：⑤が2つの財布を1つにする

[`厚生年金/収支計算/`](../papers/001365945/プログラム/厚生年金/収支計算/)。

### 入り口の問い（`cntl.c:148-163`）

```c
printf("\n厚年勘定に国年勘定を足しこんでカット率を作成しますか？\n");
printf("０：行わない（通常試算）\n");
printf("１：行う（オプション準備)\n");
scanf("%d%*c", &Touitu);
```

原本の言葉どおり、**厚年勘定に国年勘定を足しこむ**のが中身である。

### 国民年金の収支を読む（`rdfl.c:410-425`）

`provide` ファイルを読み、`Kokusyushi[項目][年度]` に入れる。

### 厚生年金の表に足しこむ（`shus.c`）

```c
// 国民年金の分の基礎年金給付を、厚生年金の給付の表に足す（99〜110行目）
E3dxb[1][6][k][dx] += ( Kyosdx[0][7][0][k][x] + Kyosdx[0][8][0][k][x] );
…

// 国民年金の保険料を足す（300〜304行目）
Cc[1][1][k] += Kokusyushi[0][k];

// 国民年金の積立金（2022年度末 12.429兆円）と、収入・支出を足す（370〜404行目）
Cc[1][20][22] += 124290.0E+8;
Cc[1][ 9][k] += ( Kokusyushi[1][k] + Kokusyushi[2][k] );
Cc[1][10][k] += Kokusyushi[3][k];
Cc[1][17][k] += ( Kokusyushi[5][k] + … + Kokusyushi[8][k] );
```

これで `Cc[1]`（厚生年金）の表が、**国民年金と厚生年金を合わせた1つの財布**になる。

### 基礎と比例に同じカットをかける（`shus_calc.c`）

給付費を集計する `shus_ave()` は、`Touitu` で分岐する（74〜176行目）。

| | 報酬比例の給付 | 基礎年金・定額の給付 |
|---|---|---|
| 通常（`Touitu == 0`） | `Escutrrh`（⑤が探すカット） | `Escutrrt`（④が決めたカット） |
| 一致（`Touitu >= 1`） | `Escutrrh` | **`Escutrrh`（同じもの）** |

通常は基礎年金のカットを④から受け取って固定し、報酬比例のカットだけを探す。
一致のときは**どちらにも同じカット `Escutrrh` を使い、それを探す**。均衡条件
（`f1 = Cc[20][2119年度末] − Cc[11][2120年度] × Ca`）は同じで、財布が合算されている点だけが違う。

探し終えたら、基礎年金のカットを統一カットで上書きする（337〜343行目）。

```c
if(Touitu>=1){
    Escutrrt[k][x] = Escutrrh[k][x];     // 基礎年金のカット ＝ 統一カット
}
```

所得代替率は「比例 × `Escutrrh` ＋ 基礎 × `Escutrrt`」なので、両方とも同じ年度に調整が終わる。

## 結果

| ケース | | 所得代替率 | 報酬比例 | 基礎年金 | 調整終了（比例／基礎） |
|---|---|---|---|---|---|
| 過去30年投影 | 通常 | 50.4% | 24.9% | 25.5% | 2026 ／ 2057 |
| 過去30年投影 | **一致** | **56.2%** | 22.9% | **33.2%** | **2036 ／ 2036** |
| 高成長実現 | 通常 | 56.9% | 25.0% | 31.9% | 調整なし ／ 2039 |
| 高成長実現 | **一致** | **61.2%** | 25.0% | **36.2%** | **調整なし ／ 調整なし** |

- 過去30年投影では、基礎年金の調整が**2057年度から2036年度へ21年短く**なり、基礎年金は
  25.5% → 33.2% に上がる。そのぶん報酬比例は2036年度まで調整が延びて 24.9% → 22.9% に下がる。
  合計は +5.8pt
- 厚生労働省の説明（過去30年投影で2057年度 → 2036年度、所得代替率は3.6〜5.8ポイント程度上昇）
  と一致する（[年金制度の仕組みと考え方 第7](https://www.mhlw.go.jp/stf/nenkin_shikumi_007.html)）
- 高成長実現の一致は、公表の財政見通し（詳細結果等2 No.21）と照合して2,134項目・不一致0、
  所得代替率 61.1848667937229% が15桁一致する（数式モデル §15）

**合計が上がるのはなぜか。** 厚生年金の財布には余裕があり、国民年金の財布は苦しい。
別々に均衡させると、苦しい国民年金に合わせて基礎年金だけが深く削られる。1つの財布にすると
厚生年金の余裕が基礎年金にも回り、両方を浅めに削るだけで全体が均衡する。

## 応用：一致の下では「拠出金の按分」は関係なくなる

2つの財布が1つなら、基礎年金拠出金をどちらの財布がどれだけ持つか（頭割り、
[基礎年金拠出金.md](基礎年金拠出金.md)）は、**財布の中での付け替え**にすぎなくなる。

[3号廃止の検証](../検証/3号廃止/README.md)では、これが実際に確かめられている。
3号に保険料を課すとき、拠出金の按分を移す設計（第1号移行型）と据え置く設計（按分据置型・国年充当）は、
通常の2段階では結果がまったく違う（36.1% と 57.9%）。ところが調整期間の一致の下では、
**2つは15桁まで同じ答え（57.52%）**になる。

## 実装の注意

- 原本は、④の2周目（`CUT_KOTEI=1`）で `read_cut.c` が開いていないファイルを閉じて落ちる。
  このリポジトリでは移植パッチ（`検証/実行/patches/glibc-portability.patch`）で直してある
  （計算結果には影響しない）
- ⑤は統一カット率を `YOBI` と `YOBI2` の2組のファイルに書くので、同じ番号にすると壊れる。
  `run_pipeline.sh` は同じ番号を指定すると止まる
- 国民年金の積立金の初期値（2022年度末 12.429兆円）は、⑤の中に直接書かれている
